# A2 个体运动量：速度 / 方向 / 加速度

## 任务

对每个个体计算速度、方向、加速度，画出分布图。

## 结论

**1. 五个场景的速度分布全都不止一个峰 —— 这是最重要的发现。**

如果只看均值（2.29 / 1.04 / 1.07 / 0.80 / 0.71）会漏掉关键信息。
实际每个场景都是**双峰或三峰**：

- **Hotel 大堂**：最极端。在 0 m/s 处有一个**极高的尖峰**，
  然后 1.0–1.5 m/s 处又一个峰。这说明大堂里混着两类人：
  **站着不动的**（等电梯、聊天、前台办理）和**正在走动的**。
  单看均值 1.04 m/s 会错误地以为"大家以 1 m/s 匀速走"。
- **Zara02** 同理，0 处有尖峰——对应商业街上**驻足看橱窗**的人。
- **ETH**：主峰在 2.3–2.6 m/s，非常高且窄，同时在 0 附近有一小撮。
  **注意：ETH 的行人是在"过马路"，不是"散步"。** 2.3 m/s 已经接近
  慢跑速度，这个数值本身就说明场景的行为语义。

**2. 速度的物理量级是对的，可以放心用。**
正常人自由步速约 **1.34 m/s**（Weidmann 模型）。本数据集里
zara01（1.07）、hotel 行走分量（约 1.3）、students03（0.71，因为人群密集被压慢）
都在合理范围。ETH 的 2.29 m/s 偏高但符合"过马路赶时间"的设定。

> 这里有个容易踩的坑，值得记一笔：ETH/UCY 的标注文件 `frame` 字段步长是 **10**
> 而不是 1（视频 25 fps，每 10 帧存一个点）。如果直接把 frame 当成帧号去乘 0.4，
> 或者把它当秒数，算出来速度会**差 10 倍**，全都变成 0.1 m/s 左右，
> 看起来像"人在爬"。正确做法是 `t = frame / 25`，即相邻点间隔 **0.4 s**。

**3. 方向分布暴露了"双向人流"结构。**
看 `a2_kinematics_all.png` 第二行：

- **ETH / Hotel / Zara02 / Students03 都是明显的双峰**，
  即在 ±180° 两端各有一堆方向。这不是"大家朝两个相反方向走"这么简单——
  它说明这些通道是**双向通行的**，双向流必然带来**对头避让**。
- **Zara01 相对更集中**（方向集中度 R=0.044，是五者里最低的），
  说明这条街的人流方向稍整齐一些。

**4. 加速度比直觉的小，而且大部分是"转向"而不是"加速"。**
加速度均值都在 0.11–0.46 m/s²，P95 也只有 0.4–1.2 m/s²，
远小于人的生理极限（正常步行起步约 1 m/s²）。
把加速度分解成切向/法向后发现：**横向加速度普遍大于切向加速度**
（ETH 0.306 vs 0.034；hotel 0.130 vs 0.0005）。
结论：行人的加速度主要来自**改变方向（绕开别人、拐弯）**，
而不是**改变快慢**。这是一个很干净的结论——
**避让行为体现在横向，不体现在加减速上。**
唯一例外是 ETH，切向加速度也不小（0.034），说明过马路时确实在主动调整步速。

**5. 横向加速度的量级排序：ETH(0.306) > Hotel(0.130) > Students03(0.114) > Zara02(0.081) > Zara01(0.088)。**
ETH 遥居第一，是第二名（hotel）的 2.4 倍。
所以 ETH 不仅"走得快"，而且"变向剧烈"——
结合轨迹图看，是因为行人在路口中不断左右调整路线穿越车流。

**6. 一句话总结：** 均值会骗人。五个场景的速度、方向分布都是多峰的，
说明每个场景都至少混了两种行为模式；而加速度分解表明，
**行人互动主要发生在横向（转向避让），不是纵向（加减速）**。
